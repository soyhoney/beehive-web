# 기존 사이트 점검 결과

`http://www.beehivecorp.co.kr` — 신규 제작을 판단한 근거.
2026-08-08 ~ 08-11 직접 조회해 확인한 내용이다.

## 구조

임대형 홈페이지 빌더 위에 올라가 있다.

```
onclick="location.href='http://beehivecorp.urr.kr/page/?5'"
Server: Microsoft-IIS/10.0
Set-Cookie: ASPSESSIONID...        ← Classic ASP
```

콘텐츠가 `urr.kr` 빌더 서버에 있어 **서버 코드를 손댈 수 없다.**
자동 견적 같은 기능은 애초에 구현이 불가능한 구조였다.

## 확인된 문제

### HTTPS 미적용

```
$ curl https://www.beehivecorp.co.kr/
curl: (35) Recv failure: Connection reset by peer     # 3회 재시도 모두 동일
$ curl -I http://www.beehivecorp.co.kr/
HTTP/1.1 200 OK
```

443 포트 연결 자체가 거부된다. 개인정보를 수집하는 페이지에 암호화가 없는 상태.

> **표현 주의** — 이름 · 연락처는 고유식별정보가 아니므로 법령상 전송 시 암호화가
> *명시적 의무*인 항목은 아니다. "안전조치 미흡으로 지적받을 소지가 있다" 정도가 정확하다.
> "명백한 법 위반"으로 말하면 반박당한다.

### 개인정보처리방침이 부동산 분양대행사 약관

원문 그대로:

```
수집항목(필수) : 이름, 연락처, 생년월일등은 제3자인 분양대행사에게 제공될수있습니다.
개인정보 수집방법 : 홈페이지(관심고객등록)
이용목적 - 분양상품에 대한 주요사항 안내, 고지, 분양상담 및 이벤트 등 광고성 정보전달
...청약당첨후 계약시 이벤트 상품권지급등에 이용될수있으며
- 보존 항목: 이름, 휴대번호, 예약일자
```

**위치**: 메인 페이지 HTML 안의 `<div class="pop-layer3">`, 기본 `display: none`.
이걸 여는 트리거는 찾지 못했다 — 즉 **현재 화면에는 노출되지 않는다.**

그럼에도 문제인 이유:
- 검색엔진은 숨겨진 텍스트도 수집한다
- 개인정보처리방침은 본래 **공개 의무**가 있는 문서인데 볼 방법이 없다

### 견적 폼이 iframe으로 삽입됨

```html
<iframe src="https://zippy-medovik-0a8761.netlify.app"
        style="width:100%; min-height:900px; border:0;">
```

별도 Netlify 앱을 홈페이지에 끼워 넣은 구조. 데이터는 구글 앱스 스크립트로 전송된다.

**폼 자체는 잘 만들어져 있다.** 카테고리 6종, 조건부 분기, 일정 미정 처리, 파일 첨부까지
설계가 꼼꼼해서 **새 사이트의 문항 구조를 여기서 거의 그대로 가져왔다.**

문제는 붙이는 방식이다:
- iframe 내용은 부모 페이지 콘텐츠로 색인되지 않는다 → 검색에 안 잡힘
- 부모가 `http://` 라 브라우저가 "안전하지 않음"을 표시
- 높이가 900px로 고정 → 모바일에서 어긋남 (🔎 코드 기준 추론, 실기기 미확인)
- 홈페이지 · 폼 · 데이터가 각각 다른 서비스에 흩어져 있음

### 그 외

| | 내용 |
|---|---|
| 죽은 CDN | `cdn.rawgit.com` (2019년 종료) 참조 → 폰트 로드 실패 |
| jQuery | `jquery-latest.min.js` — 배포 중단된 URL |
| 클라이언트 페이지 | `/page/?10` 에 "페이지 내용을 삽입해 주세요!" 노출 |
| 단일 HTML | 전 페이지가 121KB 한 파일, 인라인 스타일 · 주석 잔해 다수 |
| 모바일 | 레이아웃 깨짐 (클라이언트 직접 확인) |
