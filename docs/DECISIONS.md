# 설계 결정 기록

왜 이렇게 만들었는지. 나중에 "이건 왜 이렇게 돼 있지?" 싶을 때 보는 문서다.

---

## 서버를 두지 않는다

정적 사이트 + 구글 시트 조합으로 간다. **월 고정비 0원**이고, 서버가 없으니 장애날 것도 없다.

클라이언트는 아직 매출이 본격화되지 않은 단계다. 초기부터 서버 · DB 비용을 태우는 것보다
데이터를 먼저 쌓고, 필요해지면 그때 옮기는 게 맞다는 판단.

이관 시점의 기준은 이렇게 잡았다 — 월 문의 100건 초과 / 재구매 이력 조회 필요 /
결제 도입 / 통계 대시보드 필요. `supabase/schema.sql` 에 옮겨갈 스키마를 미리 정의해 뒀다.

## Vercel이 아니라 Netlify

**Vercel Hobby 플랜은 약관상 상업적 사용이 금지된다.** 회사 사이트는 Pro($20/월) 이상이어야 한다.
Netlify는 무료 플랜에서도 상업적 사용을 허용하므로 "월 0원"이 사실이 된다.

## 관리자 화면을 만들지 않는다

로그인이 필요하면 서버가 필요하고, 서버가 생기면 비용 · 장애 · 보안 책임이 따라온다.
특히 **고객 개인정보를 직접 만든 시스템에 담는 순간 사고 시 책임이 우리에게 온다.**
구글 시트에 있으면 그건 구글의 인프라다.

대표도 "개발 노노"라고 명시했다. 관리 UI는 **구글 시트 자체**가 대신한다.

## 견적 문항을 선택형으로 바꿨다

기존 폼은 예산 · 인원 · 기간 · 분량을 전부 자유 입력으로 받았다.
이걸 구간 선택으로 바꾼 이유는 둘이다.

1. 입력 부담이 줄어 이탈이 적다
2. **정형화된 값이라야 나중에 견적 자동 산출의 근거가 된다**

예외를 위해 `직접 입력` 선택지를 남겨 뒀다. (`src/lib/quote-flow.ts`)

## 자동 견적을 "예상"까지만 낸다

통번역은 조건에 따라 금액 편차가 크다. 자동 산출한 금액이 실제와 어긋나면 그대로 회사 손해다.
그래서 자동 산출이 가능한 건만 예상 금액을 보여주고, 나머지는 접수 확인만 하고
담당자가 확정 견적을 내도록 했다. (`src/lib/pricing.ts`)

현재 자동 산출 대상은 교육(E) 개인·그룹 수업뿐이다. 문항에 단가가 명시된 유일한 갈래라서다.

## 첨부파일은 드라이브 저장을 "실패해도 되는 단계"로 둔다

드라이브 권한이 없으면 저장만 건너뛰고, 파일은 담당자 메일에 첨부된다.
접수 자체는 성공한다.

권한 설정 하나 때문에 고객의 문의가 통째로 실패하는 건 말이 안 된다.
나중에 권한을 승인하면 코드 수정 없이 드라이브 보관이 자동으로 시작된다.
(`apps-script/Code.gs` 의 `saveToDrive_`)

## 파일 본문을 RAW_JSON과 분리한다

구글 시트 셀 한도가 5만 자다. base64 파일을 응답 JSON에 섞으면 바로 넘긴다.
그래서 payload 최상위에 `files` 로 따로 싣는다. (`src/lib/submission.ts`)

## 폰트를 자체 호스팅한다

Pretendard Variable을 동적 서브셋 92조각으로 `public/fonts/` 에 직접 뒀다.
전체는 2MB지만 브라우저가 화면에 쓰인 유니코드 구간만 받아 실제 전송은 100~150KB다.

**외부 CDN을 쓰지 않는 이유**: 기존 사이트가 2019년 서비스 종료된 rawgit CDN을 물고 있어
폰트가 아예 로드되지 않고 있었다. 같은 실수를 반복하지 않는다.

## 한국어를 확정한 뒤 영문을 복제한다

`src/lib/content/` 에 언어별 콘텐츠를 분리하고, 화면 컴포넌트에서 문자열을 걷어냈다.
한 · 영이 같은 타입을 구현하므로 **번역 누락은 컴파일 단계에서 걸린다.**

영문은 `src/lib/i18n.ts` 의 `EN_ENABLED` 로 제어한다. false인 동안에는
`/en/` 경로가 생성되지 않고 토글도 숨겨져서, **반쯤 번역된 화면이 공개될 일이 없다.**

지금 번역하지 않는 이유: 클라이언트 자료가 들어오면 문구가 바뀐다. 두 번 번역하게 된다.

**주의** — 통번역 전문 기업의 영문 페이지는 문장 완성도가 곧 실력의 증명이다.
AI 초안을 그대로 올릴 수 없고, 대표 검수가 반드시 필요하다.

## 언어 전환은 경로 분리(`/en/`)로 한다

클라이언트 사이드 전환은 검색엔진이 색인하지 못하고 영문 링크 공유도 안 된다.
해외 고객에게 영문 주소를 보내는 게 목적이므로 경로를 나눈다.

## 블로그는 연동만 한다

대표가 원한 건 "네이버 블로그 최신 글 3~5개를 썸네일로 노출 + 클릭 시 이동"이다.
사이트에 별도 게시판을 만들면 **같은 글을 두 곳에 써야 하고**, 결국 한쪽이 비게 된다.
빈 게시판은 없느니만 못하다. (기존 사이트 클라이언트 페이지가 그 상태였다)

새 창으로 열어 우리 사이트가 닫히지 않게 하고, 홈 하단에 배치해 이탈 손실을 줄인다.

## 고객 후기는 작성 폼이 아니라 인터뷰 형식으로

B2B 서비스에서 자유 작성 게시판은 스팸 · 관리 부담만 크고 실제로 잘 안 쓰인다.
고객 수도 수십 곳 수준이다.

수집은 구글폼으로 하고, 사이트에는 **회사 로고 · 인물 사진과 짧은 코멘트**를 배치하는
쇼잉 형태가 맞다.

## 개인정보처리방침을 새로 썼다

기존 방침은 **부동산 분양대행사 약관**이 그대로 들어가 있었다.
실제 수집 항목(업체명 · 담당자 · 이메일 · 휴대폰 · 문의 내용)에 맞게 다시 작성했다.
(`src/app/privacy/page.tsx`)

## 서비스 카드에는 사진을 넣지 않는다

전환이 목적인 구간이라 텍스트 카드로 유지한다. 사진은 대표 사례 섹션에서 쓴다.

## 클라이언트 로고를 히어로 바로 아래에 둔다

식약처 · 대사관 · 지상파가 깔린 로고월이 가장 강력한 신뢰 자산이다.
**신뢰를 먼저 확보하고 견적을 유도**하는 순서가 맞다.
